# Recommender Feed

A personal reading feed, ranked by LLM agents. Fetches from your sources (RSS or plain
listing pages), triages and summarizes every new item with a cheap model (Haiku), then
ranks the unread queue by **marginal value** with a stronger model (Opus 5) — an item's
position accounts for what's ranked above it, so redundant coverage gets discounted.
Your ratings ("critical" → "not worth reading") and notes feed a taste profile the
system regenerates over time. A discovery agent with web search chases your short-term
quests and can propose new permanent sources, which only you can approve.

## Setup

```bash
make setup                                # python venv + npm install
mkdir -p data
echo 'ANTHROPIC_API_KEY=sk-ant-...' > data/.env
chmod 600 data/.env
```

Without an API key the app still runs: it fetches RSS sources and shows a chronological
feed; triage/ranking/discovery are skipped.

## Running

Development (two terminals, open http://localhost:5173):

```bash
make dev-backend
make dev-frontend
```

Single-process (builds the frontend, serves everything at http://localhost:8000):

```bash
make run
```

Run the pipeline (fetch → triage → discovery → rank → profile) manually:

```bash
make pipeline        # or hit ↻ Refresh in the UI
```

Schedule it (7:30 / 12:30 / 17:30 / 21:30 daily via launchd; missed runs coalesce on wake):

```bash
make schedule
```

### Always-on (no terminal needed)

```bash
make install      # builds, then registers a launchd agent: starts at login, restarts on crash
make restart      # after code changes: rebuild + bounce
make status       # show server + pipeline launchd state
make uninstall
```

The app is then permanently at http://localhost:8000. To get a dock icon / standalone
window, open that URL in Chrome and choose **⋮ → Cast, save, and share → Install page as
app** (the site ships a PWA manifest).

**macOS caveat:** launchd-spawned processes cannot read files under `~/Documents`,
`~/Desktop`, or `~/Downloads` (TCC privacy protection — they fail with "Operation not
permitted" and no prompt is shown). If this repo lives there, both `make install` and
`make schedule` jobs will die on startup. Either keep the checkout somewhere unprotected
(e.g. `~/Developer/`, with a symlink from `~/Documents` if you like), or grant
**Full Disk Access** to the Python binary in System Settings → Privacy & Security.
`launchd/*.plist` are templates; `make` substitutes `__REPO__` with the checkout path.

## How it learns

- **Ratings** — 4 tiers: critical / worth it / fine / not worth it. Rate after reading.
- **Notes** — the optional "why?" box; quoted verbatim into the taste profile.
- **Instructions** — the text box on the Feed page. *Quests* ("find things about the
  recent Hugging Face event") expire after 14 days or when you confirm them done.
  *Standing preferences* ("less interpretability research") persist.
- **Taste profile** — regenerated by Opus from your ratings + notes every ~8 ratings or
  2 weeks; it's what the triage/ranking prompts actually read. See it at `/api/profile`.

## Costs

Hard caps per run: ≤60 triage calls (Haiku), 1 ranking call and ≤1 discovery call
(Opus, ≤8 web searches). Roughly $0.50–0.75/run; the per-run estimate is shown next to
the Refresh button.

## Layout

- `backend/app` — FastAPI + SQLite (WAL). `services/` holds the pipeline stages;
  `app/pipeline` is the orchestrator (`python -m app.pipeline`), same code path for
  launchd and the UI's Refresh button.
- `frontend/` — React + Vite, talks only to `/api/*`.
- `data/` — SQLite db, logs, `.env`. Gitignored.

## Converting to a hosted webapp later

The design is deliberately deployment-portable:

1. The frontend talks to the backend only via `/api` HTTP calls — no local coupling.
2. `make build` + `uvicorn app.main:app` is a single self-contained web process; put it
   behind any host (Fly/Render/VPS) and add an auth layer in front of `/api`.
3. The pipeline is a plain CLI (`python -m app.pipeline`) — swap launchd for cron, a
   container scheduler, or a worker dyno without code changes.
4. Config is env-var based (`ANTHROPIC_API_KEY`, `FEEDAPP_DATA_DIR`).
5. SQLite → Postgres is the only real migration; the schema is vanilla SQL and all
   SQLite-specific code lives in `backend/app/db.py`.
